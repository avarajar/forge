Five visions for the Forge console

Five radical visual directions, each with a clickable mockup, screenshots at 1440×900, scores from two judges (one looks at daily use by someone supervising 5 to 15 agents, the other looks at the design) and the ideas worth harvesting even if the full direction is not adopted.

Summary

DirectionDaily useDesign criticAverageIn one line
Daily-use judge: picks Mission Control Its test is how many seconds it takes to know who is blocked and be able to unblock them. Mission Control wins: a «Needs you» lane sorted by age with the exact command and Allow 1 / Always 2 / Deny 3 / Reply buttons, state counters, color only for state, and a Manifest whose verb follows the state. It asks to adopt it with changes: drop the sweep on the tiles and slow the blinking after the first minute, remove the wall of 8 tiles (it repeats the Manifest), swap the circular gauges for bars, build a real responsive layout, and add NORMAL/INSERT, the on-screen keys and the events panel from Terminal-native.
Design critic: picks Foundry It is the only direction whose concept comes from the product: a tool called Forge where each session is a furnace and its heat shows its state. A single state language, the most memorable and the most its own. But with conditions: a flat level without rivets or bevels for Skills, Accounts, Memory and modules; separate «needs you» from «working» (hazard stripes plus a diamond); smaller condensed titles; real labels in aria and tooltips; and fix the margins and chip collisions. Then harvest from the other four.

My recommendation

Do not adopt any direction in full. Keep the current design (the refresh already on the branch) and stitch Mission Control's information architecture onto it. The two judges agree more than it seems: the daily-use judge picks it, and the design critic credits it with the best architecture for real work; what the critic rejects is its generic skin, not its structure. Foundry has the best identity but scores 4 on what matters most (seeing who needs you), and its own required fixes leave it almost flat. Harvesting is cheaper than rewriting the console, and these pieces fit the code that already exists.

In this order:

  1. «Needs you» lane or band above the list: the agent's exact command or question inline, with Allow / Always / Deny / Reply and their keys 1–3, to unblock without opening the tab. Claude Code's hooks already deliver the event; what is missing is storing the prompt text.
  2. Color only for state, task types as outlined labels, and redundant shape (dot, ring, diamond, cross) for accessibility. This touches TYPE_STYLES in config/types.ts.
  3. Row of figures in the header with Calm focus's state sentence («Two sessions are waiting for you.») and Editorial's «tightest limit 94%»; the same counters go to document.title and to the desktop app's menu bar.
  4. Action verb that follows the state on each row (Approve, Reply, Fix, Resume, Open) and «waiting for 2m 14s».
  5. NORMAL/INSERT indicator with a ⌃b prefix in TaskDetail. It solves the real problem of where keystrokes go, and both judges highlight it.
  6. tail -f-style events panel instead of toasts, plus each session's state history with how long each permission waited.
  7. Later, if per-session output volume is recorded: activity sparklines. Today useTerminalMetrics only keeps the latest value.

What I discard: terminal on paper (Editorial, Calm focus), sweep animations, 270° gauges, themed vocabulary (Strike, Quench) and textures. If you later want more brand character, take from Foundry only the heat strip on each row's edge and the hazard stripes for permissions.
