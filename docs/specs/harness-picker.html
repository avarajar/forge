Elegir el harness al arrancar una task en Forge

Sin tocar nada, todo sigue igual: cada cuenta trae su harness por defecto y hoy ese es Claude Code. Lo nuevo es un selector en el formulario, un badge en cada sesión, y que CW recuerda con qué arrancó cada una.

2 · Dónde vive la decisión

Tres niveles, del más general al más puntual. El de abajo gana. Si no defines ninguno, es Claude Code, igual que hoy.

Nivel 1

Cuenta

Cada cuenta tiene un harness por defecto, que se fija al crearla. La cuenta work puede ser Claude y la personal Codex.

cw account add personal --harness codex
Nivel 2

Proyecto

Un proyecto puede forzar un harness distinto al de su cuenta. Útil si un repo funciona mejor con uno.

cw project register ~/x --harness pi
Nivel 3

Esta task

Lo que eliges en el formulario de Forge, o el flag en la terminal. Aplica solo a esa sesión.

cw work app SEI-214 --harness codex

3 · Qué pasa cuando le das Start con Codex

Forge

Manda la elección al servidor

El mismo POST de hoy con un campo más.

POST /api/cw/start
{ "project": "seimseim-reservas", "task": "SEI-214", "harness": "codex" }
Forge · PTY

Abre la terminal y lanza CW

cw work seimseim-reservas SEI-214 --harness codex
CW

Prepara el worktree y el contexto

Crea el worktree en .tasks/SEI-214 y enlaza los .env. Si hay LINEAR_API_KEY, trae el ticket de Linear y lo escribe en TASK_NOTES.md; si no, Codex arranca sin él, porque no tiene MCP.

CW · driver

Delega en el driver de Codex

Un archivo pequeño sabe cómo arrancar Codex, dónde están sus credenciales y qué soporta. Codex arranca ya dentro del worktree.

lib/harnesses/codex.sh
CODEX_HOME=~/.cw/accounts/work/codex codex "$(cat init_prompt.txt)"
CW · sesión

Recuerda con qué arrancó

Cuando reanudes, aunque sea desde la terminal sin flags, vuelve a abrir Codex.

~/.cw/sessions/seimseim-reservas/task-SEI-214/session.json
{ "status": "active", "opens": 1, "harness": "codex" }
Forge

Lee el campo y pinta el badge

La sesión de Codex se ve al lado de las de Claude en la misma lista y en las mismas pestañas.

5 · Qué sigue igual y qué cambia

SituaciónComportamiento
Arrancas una task sin elegir harnessIgual que hoy: Claude Code
Sesiones que ya existen en ~/.cw/sessionsIgual: sin campo harness se asume Claude Code
Reanudas una sesiónAbre con el mismo harness con que se creó, aunque no pases flags
Cuenta con harness distinto a ClaudeEl selector arranca en ese harness. Puedes cambiarlo para una task puntual
Harness no instalado en la máquinaAparece apagado en el selector con el motivo. Nunca falla al arrancar
Hooks, skip permissions, agent teamsSolo se muestran y aplican cuando el harness es Claude Code
Task de tipo LoopSolo con Claude Code: /loop es un comando suyo. El selector desactiva los demás harness
Ticket de Linear, GitHub o Notion como taskCW lo trae a TASK_NOTES.md antes de lanzar, para cualquier harness. GitHub siempre, vía gh; Linear y Notion solo con LINEAR_API_KEY / NOTION_TOKEN. Sin token, solo Claude Code lo lee, por MCP
